## What is different about Word — read before starting

### 1. The file has a UTF-8 BOM

`"encoding": "utf-8-sig"` in the config below, **not** `"utf-8"`. Get this wrong and the BOM is either duplicated into every part or stripped from the source — both show up as a whole-file diff.

### 2. `ListChartShapes` and `ListSmartArtShapes` are `internal`, not `private`

They are called from **`WordAiAddIn/TaskPaneHost.cs`**, outside the class:

```bash
grep -n "WordTools.List" WordAiAddIn/TaskPaneHost.cs
```

The partial-class split keeps them reachable (same class, same assembly), so this works — but **do not "tidy" either to `private`**. The member-set diff in Step 6 catches it if you do, because the accessibility keyword is part of the captured line.

### 3. `RetryTransientCom` stays in the **core** file, not `.Charts.cs`

Both of its current callers are chart code, so putting it in `.Charts.cs` looks right. It is not. `RetryTransientCom` is general COM-retry infrastructure by name and design; burying it in a chart file means the next non-chart caller either reaches into the wrong file or duplicates it. **This is a deliberate decision — leave it in core.** (Same for `TransientComHResults`, the HRESULT table it reads.)

### 4. `ParagraphIndexResolver` is a nested `private sealed class`, not a method

The script handles it — it matches on the 8-space indent, and the class's own members are indented 12 spaces so they are not mistaken for top-level members. Just make sure it appears in exactly one group (`Content`).

### 5. Three areas are non-contiguous today

Charts sit in two chunks, content in two, `apply_commands` in two (`InsertTocCmd` is stranded after the image helpers). The script assigns by name so this is handled — but it is why Word's diff will look the largest of the three.

## Step 1 — Write the split config

Create `.split-work/word.json` with **exactly** this content (note `utf-8-sig` and `headerLines: 13`):

```json
{
  "source": "WordAiAddIn/WordTools.cs",
  "encoding": "utf-8-sig",
  "headerLines": 13,
  "tailLines": 2,
  "groups": {
    "Html":            ["HtmlBlockTags","HtmlInlineTags","ParseHtmlFragment","ValidateHtmlTags","WriteInlineNodes","InsertHtmlFragment"],
    "Content":         ["ParagraphIndexResolver","FindText","GetHeadings","GetDocumentContext","InsertContent","HtmlReadBlocksMaxParagraphs","TextReadBlocksMaxParagraphs","ReadBlockAsHtml","ReadBlocks","ReplaceBlocks"],
    "Charts":          ["WriteChartData","ListChartShapes","ReadChart","EditChart"],
    "Tables":          ["ResolveTable","AddTable","EditTable","ReadTable"],
    "SmartArt":        ["ResolveSmartArtLayout","ResolveSmartArtGalleryItem","AddSmartArt","ListSmartArtShapes","ReadOneSmartArt","ReadSmartArt","EditSmartArt"],
    "Commands":        ["RequiredFields","NonNullFields","KnownCommandKinds","ApplyCommands","SetRunProperty","SetHeading","FindReplace","ResolveTargetParagraphs"],
    "Commands.Style":  ["HighlightColors","KnownTextStyleFields","KnownParagraphStyleFields","UpdateTextStyle","UpdateParagraphStyle","BulletPresets","ApplyBulletPreset","CreateParagraphBullets","DeleteParagraphBullets"],
    "Commands.Blocks": ["DeleteBlocksCmd","MoveBlocksCmd","UpdateImageProperties","InsertTocCmd"],
    "Images":          ["ValidateLocalImagePath","AddImage"]
  }
}
```

**Stays in `WordTools.cs`** (9 members, not listed): `ModeByDoc`, `SetMode`, `ModeFor`, `AlwaysAllowedTools`, `Execute`, `AddComment`, `ActiveDoc`, `RangeAfterBlock`, `EndOfDocumentRange`.

The `Commands.Style` and `Commands.Blocks` suffixes produce `WordTools.Commands.Style.cs` and `WordTools.Commands.Blocks.cs` — dotted suffixes are fine.

**Why `apply_commands` splits three ways:** together those 20 members are ~660 lines, over the ~450 ceiling. The cut is: the gateway and target-matching (`Commands`), the style/bullet commands (`Commands.Style`), and the block-structure commands (`Commands.Blocks`). If the two smaller ones come out under ~150 lines each, merging them back into one `Commands.Rest` is a reasonable call — but decide before Step 3, not after.

## Step 4 — Add the 9 files to the csproj

```bash
cd /c/dev/officeoffice
python - <<'PYEOF'
import io
p = "WordAiAddIn/WordAiAddIn.csproj"
t = io.open(p, encoding="utf-8-sig").read()
anchor = '    <Compile Include="WordTools.cs">\n      <SubType>Code</SubType>\n    </Compile>\n'
assert anchor in t, "anchor not found - open the csproj and add the entries by hand"
parts = ["Html","Content","Charts","Tables","SmartArt","Commands","Commands.Style","Commands.Blocks","Images"]
add = "".join(
  '    <Compile Include="WordTools.%s.cs">\n'
  '      <SubType>Code</SubType>\n'
  '      <DependentUpon>WordTools.cs</DependentUpon>\n'
  '    </Compile>\n' % s for s in parts)
io.open(p, "w", encoding="utf-8-sig").write(t.replace(anchor, anchor + add, 1))
print("csproj: added", len(parts), "Compile entries")
PYEOF

grep -c "<Compile" WordAiAddIn/WordAiAddIn.csproj
```

**Expected:** `added 9`, then `15`.
