## What was built

- **`PptChartTypeMap` corrected**: `"bar"` was 51 (xlColumnClustered) — a silent wrong result even on a successful call — now 57 (xlBarClustered). `"barStacked"` had the identical bug (52 → 58, xlBarStacked). Added `"column"`(51)/`"columnStacked"`(52) as explicit entries so both orientations are addressable under distinct names, matching `ExcelChartTypeMap`'s vocabulary exactly (verified by reading `ExcelAiAddIn/ExcelTools.cs`'s map directly, not from memory).
- **`AddChartPpt`**: unknown `kind` now throws (was silent fallback to 51); added a series/categories length-mismatch check (PP-22 Task 1 Step 4, done here since it's the same method); returns the new chart's 0-based shape index in the result text (PP-22 Task 1 Step 5).
- **`EditChartPpt`**: full rewrite.
  - Checks `shape.HasChart` up front and reports a specific "not a chart" error naming the slide/shape (was an unhelpful raw error from `shape.Chart` failing).
  - `chartType`: unknown value now throws, listing valid values from the map itself (can't drift).
  - `legendPos`: new `PptLegendPositions` map accepts natural names (`right`/`top`/`left`/`bottom`) plus the original short aliases (`r`/`t`/`l`/`b`) case-insensitively; unknown value throws. The terminal-else-to-bottom defect (any unmatched string silently became bottom) is gone. **`xlLegendPositionCorner` was considered and dropped** — its code could not be verified against a live Office install from this environment, and the plan explicitly says to drop rather than guess.
  - `dataLabels`: changed from a boolean (which silently turned labels OFF for any non-`true` value, including the string `"value"`) to a string enum `none`/`value`/`percent`, matching Excel's vocabulary exactly; `percent` calls `series.DataLabels().ShowPercentage = true`, the same call Excel's equivalent uses (confirmed this member exists on the shared underlying chart engine, since PowerPoint/Excel charts share the same COM object model here).
  - `gridlines`: now wrapped in try/catch — chart types with no value axis (pie/doughnut) throw a clear message instead of a raw COM exception.
  - Replaced the flat `"Chart updated."` with a list of exactly which properties were applied (`"Chart updated: chartType=bar, legendPos=right."`), or an explicit "nothing changed" message if no recognized parameter was provided.
- **Schema** (`entry.ts`): `add_chart.kind` and `edit_chart.chartType` share one `enum` (`column`/`columnStacked`/`bar`/`barStacked`/`line`/`area`/`pie`/`doughnut`) derived from the corrected map. `edit_chart.legendPos` gets `enum: ['none','right','top','left','bottom','r','t','l','b']` (long names first, short aliases kept for back-compat, not `corner` since it was dropped). `edit_chart.dataLabels` changed from boolean to the three-value string enum.
