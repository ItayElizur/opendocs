## What was built

- `ValidateLocalImagePath` — rejects `http(s)://`/`file://` with the same air-gapped message shape Excel's `AddImageExcel` uses, plus a `File.Exists` check Excel's version lacks (a specific "no file at '...'" error instead of an opaque `COMException`).
- `AddImage` — inline by default (`InlineShapes.AddPicture`, addressable afterwards by `apply_commands`/`updateImageProperties`'s existing 0-based index); `floating: true` for a floating `Shape` (not addressable, and the result text says so explicitly). Both paths embed the image (`LinkToFile: false`/`msoFalse`, `SaveWithDocument: true`/`msoTrue`) so the document stays portable. `afterBlockIndex` reuses `RangeAfterBlock` from PP-10 Task 1.
- Proportional sizing: `widthPoints`/`heightPoints`, either alone scales the other from natural size; neither given leaves natural size; never distorts by defaulting the unset dimension.
- Alt text: `altText?` sets `AlternativeText` on either shape type after insertion (confirmed to exist on both — see build note above).
- Inline-index reporting fix: initially considered `InlineShapes.Count - 1` for the returned index, then corrected — `InlineShapes` is ordered by *document position*, not insertion time, so a shape inserted mid-document (via `afterBlockIndex`) is not necessarily the last entry. The actual implementation finds the new shape's index by matching `Range.Start` position instead.
- Registered as `case "add_image"` in `WordTools.Execute`'s switch; confirmed **not** present in `READ_ONLY_TOOL_NAMES`/`commentOnlyExtraTools` in `entry.ts` (mutating tool, correctly gated to Track Changes/Full Autonomy only).
