## What was built

- **Task 1 (highlight):** `HighlightColors` — a 16-entry `WdColorIndex` palette map (all member names compiled clean against this project's PIA — no member had to be dropped, unlike the `MsoAutoShapeType` precedent in `ExcelTools.cs`). Wired into `UpdateTextStyle` as a tenth field; an unrecognized name throws (caught by `ApplyCommands`'s per-command handler, converted to a specific `ERROR -` line) rather than silently no-opping.
- **Task 1 Step 3/4 (general false-success guard):** `ValidateKnownFields` checks every `fields` entry against a known set for both `UpdateTextStyle` (10 fields) and `UpdateParagraphStyle` (10 fields) — a misspelled or unimplemented field name now errors by name instead of silently matching no `if` and reporting `ok`.
- **Task 2 (bullet presets):** 7 named presets (`BULLET_DISC_CIRCLE_SQUARE`, `BULLET_DIAMOND_X`, `BULLET_CHECKBOX`, `NUMBERED_DECIMAL`, `NUMBERED_DECIMAL_ALPHA_ROMAN`, `NUMBERED_UPPERALPHA`, `NUMBERED_UPPERROMAN`), each applying Word's own proven `ApplyBulletDefault()`/`ApplyNumberDefault()` and then, where the preset needs more, overriding the resulting level's `NumberStyle`/`NumberFormat`/`Font.Name` — a deliberately more conservative approach than constructing a `ListTemplate` from a gallery index (which the plan itself flags as unstable across Office versions/locales). An absent `bulletPreset` keeps the old default-bullet behavior unchanged. An unrecognized preset throws, listing valid names.
- **Task 3 (batch isolation, the still-open half):** `ApplyCommands` now numbers every result line with the command's 0-based position (`"[2] updateTextStyle: ok"`) and prepends a summary header (`"Applied 5 of 7 command(s) (2 failed)."`). The per-command `kind`-inside-`try` isolation itself was already in place from PP-5 Task 4 Step 1 — confirmed by reading the code before starting, not re-implemented.
- **Task 4 (sweep for false-success paths):** `UpdateTextStyle`, `UpdateParagraphStyle`, and `DeleteBlocksCmd` now throw a specific "no paragraphs matched target" error when `ResolveTargetParagraphs` returns empty, instead of reporting `ok` having changed nothing. `CreateParagraphBullets` and `DeleteParagraphBullets` were changed from `void` to returning a descriptive count string (`"X applied, Y heading(s)/non-list paragraph(s) skipped"`), consumed directly by `ApplyCommands`'s result line instead of a bare `ok`; `anyMutated` is only set when the count is non-zero, so an all-skipped batch no longer shows the "✓ Applied" tag. `MoveBlocksCmd` rejects an empty `blockIndexes` array.

## Real risk area — read before testing

The two Wingdings-glyph bullet presets (`BULLET_DIAMOND_X`, `BULLET_CHECKBOX`) set `ListLevels[1].NumberFormat` to specific single characters intended as Wingdings glyph codepoints, plus `Font.Name = "Wingdings"`. **This is the least certain piece of this plan** — I have no way to render and visually confirm these characters produce the intended diamond/checkbox glyphs in a real Word session; the exact character-to-glyph mapping in the Wingdings font is something I could not verify from here. If either renders as the wrong glyph or an unexpected character, that specific preset needs its `NumberFormat` character corrected (or, per the plan's own Task 2 Step 7 "scope valve," dropped from the enum entirely) — the other five presets do not depend on font-specific glyph codepoints and are lower risk. `NUMBERED_DECIMAL_ALPHA_ROMAN` is documented as narrower than genoffice's version (level 1 stays plain decimal, since this file's flat per-paragraph model has no real multi-level nesting to show the alpha/roman sub-levels) — an honest gap, not a bug.

## Deviations from plan

- The bullet-preset implementation approach (apply default, then override the resulting level's properties) is a documented, deliberate deviation from the plan's suggested "pick a gallery template + set `ListLevels[1..3]` explicitly from scratch" — chosen because it reuses Word's own already-proven default-application logic rather than constructing a list template from an index the plan itself calls unstable. This narrows what's controllable (only level 1 is touched, not a full 3-level nested scheme) but is more likely to compile and behave predictably.
- `CreateParagraphBullets`/`DeleteParagraphBullets` changed signature from `void` to `string` (a necessary consequence of Task 4's reporting requirement) — this is an internal-only signature change, not part of any public schema.
