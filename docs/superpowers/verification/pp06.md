## Deviations from plan

- Model field implemented as two coexisting DOM elements with a toggled `data-field` attribute (my own design choice, not literally specified) rather than replacing one DOM node with another on provider change — simpler, no listener-rebinding risk, and reads/writes still resolve through the same `[data-field="model"]` selector the plan's Save handler already used.
- Caught and fixed before it shipped: my first draft defaulted an absent `initialSettings.provider` to `AI_PROVIDERS[0]` (Genspark), which would have rendered the model field as a `<select>` and broken the existing "initialSettings pre-fills the form" test (which passes a flat, provider-less shape expecting a plain input). Changed the default to `'custom'`, matching this repo's actual default provider.
